# Native predicate contract composition

This proof-only harness composes the exact generated native capture and predicate
modules. `generate.py` regenerates both from current production source, rejects
stale component artifacts, and embeds their generated bytes once each under
separate namespaces. A full verifier invocation checks the imported bodies as
well as the composition; per-root checks are additional coverage evidence.

`capture_then_validate` calls the source-bound `capture_dependencies` operation,
translates every read's index offset, bucket, and stamp without dropping or adding
entries, and calls the source-bound `index_read_conflict` operation. The two
interfaces represent the captured state and a later validation state. The result
cannot be successful validation when any captured bucket has a publication stamp
at or after the reader's start. Empty raw-query results still capture their bucket
because candidate contents do not condition the native dependency loop.

The provenance exported by capture is necessary here: prefix preservation and
coverage alone would permit unrelated invented dependencies. Its stronger
`permitted_additions` contract restricts every addition to the captured index,
bucket and stamp. The composition proves that guards covering the prior read set
and the newly captured buckets cover the translated validation read set.

`publication_supplies_late_bucket` connects the exact `stamp_relation` exported by
the native publication proof to the composition's invalidation condition. The
fresh stamp must be at least the reader's start; deriving that temporal fact from
real snapshot registration, deregistration and the global atomic clock remains a
separate obligation.

This is conditional composition of source-bound operations, **not an execution of
a real concurrent history and not a whole-lookup or transaction-history refinement
proof**. The caller must justify that the two interfaces correspond to actual
states, with stable registry mapping and the stated guards. Raw candidate
completeness, pinned MVCC, native atomics/mmap, allocation and errors remain outside
this theorem. The harness is never linked into the production engine and adds no
runtime bookkeeping or locks. No Lean theorem is imported as an assumption.

Run with the installed pinned toolchain:

```sh
python3 verification/predicate_composition/generate.py --check
python3 verification/predicate_composition/test_generate.py
python3 verification/predicate_composition/run.py
```

The runner hashes all native, adapter, contract and generated inputs before and
after checking, authenticates verifier artifacts, runs the full proof plus all
five named roots, and checks six deliberately broken compositions. Wrong index,
bucket or stamp translation, ignoring the native conflict result, skipping
capture, and skipping validation must fail proof obligations. Parser/type errors,
missing roots, timeouts and changed inputs cannot count as successful checks.
